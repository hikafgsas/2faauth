# Authenticator — локальный 2FA для Android

Учебный Android-проект на Kotlin и Jetpack Compose. Откройте [инструкцию запуска](../ЗАПУСК_НА_ТЕЛЕФОНЕ.md): файлы уже находятся в созданном проекте, переносить код вручную не нужно.

## Возможности

- Список аккаунтов, поиск по сервису и имени, копирование кода нажатием на карточку.
- Круглый таймер, пересчёт по времени телефона; стандартные параметры — 6 цифр / SHA1 / 30 секунд.
- Добавление через камеру (CameraX + ML Kit), секретный Base32-ключ или `otpauth://totp/…`.
- Проверка данных перед сохранением; защита от повторного добавления одного ключа с теми же параметрами.
- SHA1, SHA256, SHA512, коды из 6–8 цифр, период 1–300 секунд. HOTP и `otpauth-migration://` не поддерживаются.
- Удаление аккаунта с подтверждением.
- Светлая, тёмная и системная темы; настройки сохраняются через DataStore.
- Блокировка при возвращении из фона через Android BiometricPrompt. На Android 11+ доступна надёжная биометрия или PIN/пароль телефона; на Android 8–10 — надёжная биометрия.
- Защита скриншотов, записи экрана и обзора приложений включена по умолчанию.

ML Kit использует встроенную модель, поэтому распознавание QR работает без предварительного скачивания модели. У приложения удалено разрешение `INTERNET`, в том числе добавляемое библиотеками. Для первого Gradle Sync интернет на компьютере необходим. [Документация ML Kit](https://developers.google.com/ml-kit/vision/barcode-scanning/android).

├── data/

Архитектура — MVVM + Repository. Compose подписывается на StateFlow, ViewModel выполняет операции через Repository, Room и криптография работают вне главного потока. Секреты не сохраняются в `SavedStateHandle`, `rememberSaveable` или `Bundle`.

## Как объяснить TOTP преподавателю

Сервис и приложение знают один и тот же секрет. Пароль пользователя для генерации кода не используется.

1. Декодируем секрет из Base32 в байты.
2. Берём Unix-время в секундах. Вычисляем `T = floor(unixTime / period)`; обычно `period = 30`.
3. Кодируем `T` как 8 байт в порядке big-endian.
4. Вычисляем `HMAC-SHA1(secret, T)` либо указанный SHA256/SHA512.
5. Последние 4 бита HMAC задают смещение. По нему берём 4 байта и убираем знаковый бит — получаем 31-битное число.
6. Вычисляем остаток от деления на `10^digits` и дополняем слева нулями.

Сервис вычисляет ожидаемый код таким же способом. Часовой пояс не влияет на Unix-время, но неверные часы телефона дадут неверные коды. Таймер приложения каждый раз считает остаток от реального времени, а не накапливает задержку последовательных `delay`.

В `TotpTest.kt` проверяются все 18 контрольных значений из Appendix B RFC 6238, включая время за пределами 32-битного диапазона. Например, для RFC-секрета и времени `59` секунд SHA1 даёт `94287082` при 8 цифрах и `287082` при 6 цифрах. [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238).

Разбор URI следует формату `otpauth://totp/Issuer:account?secret=BASE32&issuer=Issuer`: поддерживает percent-encoding, сохраняет `+` в почте, отвергает конфликтующие issuer и повторяющиеся параметры. [Формат Key URI](https://github.com/google/google-authenticator/wiki/Key-Uri-Format).

## Защита данных и границы реализации

- В Room хранится зашифрованный JSON всех полей аккаунта, включая сервис, имя и секрет. В открытом виде остаются случайный ID и время создания записи. Это шифрование полезной нагрузки, а не SQLCipher всего файла SQLite.
- AES-256-GCM использует новый случайный 96-битный IV для каждого шифрования и 128-битный тег. ID записи передаётся как AAD: перестановка шифротекста между строками не даст корректной расшифровки.
- Ключ AES создаётся в Android Keystore. Аппаратная реализация зависит от телефона; приложение не утверждает наличие StrongBox. [Android Keystore](https://developer.android.com/privacy-and-security/keystore).
- BiometricPrompt защищает вход в интерфейс. AES-ключ в этой версии не привязан к `CryptoObject`/`setUserAuthenticationRequired`: биометрия и шифрование — отдельные уровни. Это не защита от root, внедрения кода в процесс или полностью скомпрометированной ОС. [BiometricPrompt](https://developer.android.com/identity/sign-in/biometric-auth).
- Блокировка приложения изначально выключена; её надо включить в настройках и подтвердить системным диалогом. При включённой блокировке уход в фон закрывает сессию, очищает форму и прекращает чтение аккаунтов. Отмена диалога не открывает коды.
- Защита экрана изначально включена. Её можно отключить для демонстрационных скриншотов. Ограничения `FLAG_SECURE` зависят от ОС и прошивки; проверяйте их на своём телефоне.
- Код помечается чувствительным для буфера обмена. Приложение пытается очистить только собственную последнюю копию примерно через 30 секунд. ОС может ограничить доступ в фоне, а процесс может завершиться — гарантировать очистку во всех случаях нельзя.
- Облачное резервирование и перенос данных ОС отключены. Экспорта, синхронизации и восстановления секретов в этой версии нет. Удаление приложения/очистка данных уничтожает локальный доступ к аккаунтам. Резервные коды сервисов нужно хранить отдельно.
- При ошибке расшифровки записи не удаляются и ключ автоматически не заменяется. Читаемые аккаунты остаются доступны, рядом показывается число проблемных записей. Добавление блокируется, пока в базе есть нечитаемые записи: это предотвращает смешивание записей от разных ключей.

Если появился текст «Не удалось расшифровать»: не удаляйте приложение и не очищайте его данные в надежде исправить ошибку. Перезапустите приложение. Если ключ Keystore был утрачен, одна копия `vault.db` его не восстановит: потребуется заново подключить 2FA через сервис, пользуясь его резервными кодами. Автоматического сброса базы в коде нет.

## Сборка и проверки

Сохранена основа созданного Android Studio проекта: AGP 9.5.1, Gradle Wrapper 9.6.0, Android SDK 37, минимальная версия Android 8.0 (API 26). Gradle daemon использует JDK 25 из исходных настроек проекта. Добавлен KSP для генерации Room. Версии зависимостей зафиксированы в `gradle/libs.versions.toml`.

В PowerShell из корня проекта:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Отчёт JVM-тестов: `app/build/reports/tests/testDebugUnitTest/index.html`. Отчёт Lint: `app/build/reports/lint-results-debug.html`.

`VaultSecurityTest.kt` содержит отдельные инструментальные тесты Android Keystore/Room: случайный IV, round-trip, подмена AAD/шифротекста, отсутствие автоматического создания потерянного ключа, зашифрованное хранение, дубликаты и удаление. Запускаются на отдельном тестовом устройстве/эмуляторе:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

Фактические результаты локальной проверки записаны в [ПРОВЕРКА.md](../ПРОВЕРКА.md). Успешная сборка и JVM-тесты не подтверждают работу камеры, биометрии и интерфейса на конкретном телефоне; ручной список проверок есть в инструкции запуска.
