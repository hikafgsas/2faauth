# Как запустить Authenticator на телефоне

## 1. Откройте правильный проект

Проект уже заполнен здесь:

```text
C:\Users\Alex228\AndroidStudioProjects\Authenticator
```

Если эта папка уже открыта в Android Studio, ничего копировать и создавать заново не нужно. В дереве проекта раскройте `app → src → main → java → com.example.authenticator`.

На другом компьютере: скопируйте всю папку проекта, затем в Android Studio нажмите **Open** и выберите папку `Authenticator`, в которой находятся `settings.gradle.kts`, `gradlew.bat` и `app`. Не открывайте отдельно `MainActivity.kt` как самостоятельный проект. `local.properties` на другом компьютере нужно пересоздать средствами Android Studio — в нём указан местный путь к SDK.

## 2. Дождитесь Gradle Sync

1. Нажмите **Sync Now** в уведомлении об изменённых Gradle-файлах. Если уведомления нет: **File → Sync Project with Gradle Files**.
2. Дождитесь окончания загрузок и синхронизации. При первом запуске компьютеру нужен интернет для Gradle и библиотек.
3. Если предложено установить SDK, нажмите **Install missing SDK packages** и дождитесь окончания.
4. Через **Tools → SDK Manager** при необходимости установите **Android API 37**, **Android SDK Build-Tools 36.0.0** и **Android SDK Platform-Tools**. Эти версии соответствуют исходным настройкам вашего проекта.
5. В **Settings → Build, Execution, Deployment → Build Tools → Gradle** оставьте Gradle Wrapper и JDK 25 / подходящий встроенный JBR 25. В проекте уже есть `gradle/gradle-daemon-jvm.properties`, который выбирает Java 25. Отдельно менять системную Java не требуется.

Не применяйте автоматическое массовое обновление версий зависимостей во время первого запуска. Сначала соберите текущую конфигурацию.

## 3. Подготовьте Android-телефон

Нужен Android 8.0 или новее. Для сканера нужна камера, для биометрической блокировки — настроенная биометрия; на Android 11+ также доступна блокировка PIN-кодом/паролем телефона.

1. На телефоне откройте **Настройки → О телефоне**.
2. Нажмите **Номер сборки** примерно 7 раз. На некоторых телефонах пункт находится внутри раздела о версии ПО; на Xiaomi разработчик включается через версию ОС/MIUI.
3. Вернитесь в настройки и откройте **Для разработчиков**.
4. Включите **Отладку по USB**.
5. Подключите телефон кабелем, который поддерживает передачу данных, и разблокируйте экран.
6. При запросе **Разрешить отладку по USB?** подтвердите доступ своего компьютера.
7. При необходимости выберите режим USB **Передача файлов**. На некоторых прошивках отдельно требуется **Установка через USB**.

Официальная инструкция: [запуск на физическом Android-устройстве](https://developer.android.com/studio/run/device).

## 4. Запустите из Android Studio

1. В верхней панели выберите конфигурацию **app**.
2. В списке устройств выберите свой телефон.
3. Нажмите зелёный треугольник **Run ▶** или **Shift+F10**.
4. Дождитесь сборки и установки. При запросе на телефоне разрешите установку.
5. На телефоне откроется **Authenticator**. Затем приложение можно открывать обычным значком без компьютера и без Android Studio.

Эмулятор для этого не нужен. Наличие SDK 37 на компьютере не означает, что на телефоне должен быть Android с API 37: приложение поддерживает API 26+.

## 5. Проверьте на учебном QR-коде

1. На компьютере откройте картинку `demo/demo-qr.png` из папки проекта.
2. В приложении нажмите **Добавить → Сканировать QR-код**.
3. Разрешите доступ к камере. Если разрешение ранее запрещено, кнопка **Настройки разрешений** открывает настройки приложения; включите камеру и вернитесь.
4. Наведите камеру на QR-код. После чтения откроется форма с названием **Учебный стенд**, аккаунтом `student@example.test` и параметрами SHA1 / 6 цифр / 30 секунд.
5. Нажмите **Сохранить аккаунт**. Появится карточка с меняющимся кодом и круглым таймером.
6. Нажмите карточку: код скопируется. Вставьте его в подходящее тестовое поле.

Это публичный тестовый ключ. Он не подключает реальный сервис и не подходит для защиты настоящего аккаунта.

Если камеру пока проверить нельзя, откройте `demo/demo-otpauth.txt`, скопируйте ссылку, вставьте в поле **otpauth://** и нажмите **Заполнить поля из ссылки**, затем **Сохранить аккаунт**. Можно также добавить вручную:

```text
Название сервиса: Учебный стенд
Аккаунт: student@example.test
Секрет: GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
Алгоритм: SHA1
Цифры: 6
Период: 30
```

## 6. Подключите настоящий аккаунт

1. Откройте настройки безопасности нужного сервиса на компьютере и включите **приложение-аутентификатор / TOTP**.
2. Сначала сохраните резервные коды этого сервиса в безопасном месте.
3. Сканируйте выданный сервисом QR-код либо введите его секрет вручную.
4. Проверьте данные и сохраните аккаунт в приложении.
5. Введите текущий код в сервис, чтобы завершить подключение 2FA.

В приложении нет экспорта и синхронизации. При удалении приложения или очистке его данных ключи будут потеряны. Не переносите сюда единственную копию важных 2FA-ключей до завершения проверки на своём телефоне.

## 7. Темы и блокировка

- **Настройки → Оформление**: выберите системную, светлую или тёмную тему.
- **Настройки → Блокировка приложения**: включите и подтвердите системным диалогом. Сверните приложение и откройте снова — коды должны появиться только после подтверждения личности. Отмена должна оставить экран закрытым.
- **Защита экрана** включена сразу: скриншоты и снимок в обзоре приложений должны скрываться. Для скриншотов учебного интерфейса можно временно отключить её, используя только демонстрационный аккаунт.
- На Android 8–10 поддерживается надёжная биометрия без PIN-резерва; на Android 11+ можно использовать PIN/пароль устройства. Если ОС не может подтвердить личность, обхода блокировки в приложении нет.

## 8. Если телефон не появился

- Проверьте другой USB-кабель и порт, разблокируйте телефон, подтвердите RSA-запрос отладки.
- Проверьте, что включена именно **Отладка по USB**.
- Для Windows может требоваться USB-драйвер производителя. [Официальная справка о драйверах](https://developer.android.com/studio/run/oem-usb).
- В терминале Android Studio выполните:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
```

Статус `device` означает, что устройство готово. `unauthorized` — подтвердите запрос отладки на телефоне. Пустой список обычно означает проблему с кабелем, драйвером или USB-режимом. Если SDK стоит в другой папке, возьмите путь из **SDK Manager**.

## 9. Если сборка не проходит

- **SDK location not found**: откройте **SDK Manager**, проверьте установленный SDK и повторите Sync. На другом компьютере не используйте чужой `local.properties`.
- **Gradle JVM / Java version**: проект выбирает JDK 25. Проверьте Gradle JDK в настройках Studio и доступность сети для загрузки toolchain, если встроенная Java другая.
- **Could not resolve / Read timed out**: проверьте доступ компьютера к Google Maven, Maven Central и Gradle Plugin Portal, отключите **Gradle Offline Mode** и повторите Sync. Разрешение `INTERNET` в AndroidManifest к скачиванию библиотек на ПК отношения не имеет.
- **Unresolved reference** сразу после записи файлов: дождитесь Sync и выполните сборку. Если сборка показывает конкретную ошибку Kotlin, ориентируйтесь на первую ошибку в **Build Output**.
- **INSTALL_FAILED_UPDATE_INCOMPATIBLE**: уже установлена сборка с другой подписью. Не удаляйте её, если в ней есть важные аккаунты; сначала обеспечьте восстановление через сервис. Для учебной сборки без важных данных старую установку можно удалить и повторить Run.
- **Код не принимается сервисом**: включите автоматическую дату и время телефона, проверьте ключ, число цифр, алгоритм и период. Дождитесь нового интервала и попробуйте снова.

## 10. APK без подключения к Studio

В терминале проекта:

```powershell
.\gradlew.bat :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Его можно передать на телефон, открыть и разрешить установку из выбранного файлового менеджера. Это отладочная сборка для разработки. Для выпуска используйте **Build → Generate Signed App Bundle / APK** и храните ключ подписи отдельно; смена подписи влияет на возможность обновления установленного приложения.

## 11. Ручная проверка перед показом

- [ ] Демонстрационный QR считывается, форма не сохраняется без нажатия «Сохранить».
- [ ] Ошибочный QR/неправильный Base32 дают понятную ошибку.
- [ ] Повторное добавление того же ключа с теми же параметрами отклоняется.
- [ ] Код и таймер меняются на границе 30 секунд, в авиарежиме тоже.
- [ ] Копирование вставляет код без пробелов; последующая чужая копия не очищается таймером приложения.
- [ ] Аккаунт остаётся после полного закрытия и повторного запуска.
- [ ] Поиск работает по сервису и почте, удаление требует подтверждения.
- [ ] Обе темы сохраняются после запуска, клавиатура не перекрывает кнопку сохранения.
- [ ] Биометрия/PIN открывают коды, отмена — нет; после сворачивания и выключения экрана приложение закрывается.
- [ ] С включённой защитой экрана скриншот/обзор скрыты, после её отключения это поведение меняется.
- [ ] Поворот экрана и уход в фон во время сканирования не приводят к сбою камеры.

Фактически выполненные на компьютере проверки перечислены в `ПРОВЕРКА.md`. Этот список предназначен для проверки на вашем устройстве.
